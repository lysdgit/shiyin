# 拾音 Shiyin

B站音频搜索与播放器(Android 原生应用):搜索 B 站内容播放音频,或粘贴视频 / 收藏夹列表批量播放。深色 / 浅色主题,液态玻璃 dock,听歌记录。

## 功能

- **搜索**:关键词搜视频 / UP主,分页加载;UP主详情页看全部作品、播放全部、一键存为歌单
- **粘贴解析**:BV/av 号、视频链接(含 `?p=N`)、b23.tv 短链、收藏夹链接或 ID;单曲入队,多P视频与收藏夹自动创建歌单
- **歌单**:新建 / 加入曲目(去重)/ 删除 / 导出 JSON;多P视频自动聚合为歌单;新歌单封面自动取自曲目;曲目带发布时间
- **歌单备份**:设置页一键导出 / 导入全部歌单(JSON,含曲目发布时间;导入时同 ID 覆盖、其余追加)
- **听歌记录**:每次真正播放(切歌 / 自动下一首 / 单曲循环)自动记一条——歌名、播放时间、**播放地点(省 / 市)**;仅存手机本地不上传;一键重播;支持导出 CSV、可清空
- **播放器**:队列扁平化管理、列表/单曲循环、进度拖拽、倍速(0.75–2x)、睡眠定时、音质三档(切换保留进度)
- **失败处理**:音源 403 自动重新解析重试(保留进度);单曲失败自动跳下一首,连续 3 次失败暂停
- **后台播放**:前台服务 + 系统媒体通知(锁屏/通知栏控制),音频焦点与耳机拔出暂停由 Media3 托管

## 液态玻璃外观

- 底栏为 **dock 悬浮胶囊**(参考 [Kyant0/AndroidLiquidGlass → Backdrop](https://github.com/Kyant0/AndroidLiquidGlass)):内容从面板下滚过,模糊 + vibrancy + 折射(Android 13+ 有完整 lens 折射,12+ 有模糊,11 及以下自动回退实色)
- **选中的 tab 有玻璃滑块**,切换时弹簧动画滑过去;在底栏上**左右滑动**也能切 tab;拖拽时滑块**顺手指方向拉长形变**,松手**弹簧吸附回弹**;图标随滑块靠近**放大**(透过玻璃的折射感)
- **深色 / 浅色主题**可切换(设置 → 主题,即时生效)
- **全参数开放调节**(设置 → 玻璃效果 / 滑块动画):玻璃不透明度 0–100%、模糊强度 0–24dp、滑块动画过冲/速度、拖拽拉伸幅度、图标放大倍率——全部拖动实时预览

## 工作原理

### 一、整体数据流

```
 搜索 / 粘贴解析(调 B站接口)
        ↓ 产出
 ┌─ 单曲 → 加入播放队列(立即播放)
 └─ 多P视频 / 收藏夹 → 自动创建歌单
        ↓
 播放队列(扁平列表,AppStore 持久化)
        ↓ 交给 Media3 前台服务
 播放时逐首解析 CDN 直链(带 Referer 防盗链)
        ↓
 同时:切歌时写一条听歌记录(歌名+时间+地点)
```

### 二、搜索与粘贴解析

- **搜索**走 B站 `web-interface/search` 接口,分视频和 UP主两种类型;首次使用会先调
  `finger/spi` 接口获取 `buvid3/buvid4` 匿名 cookie(搜索必带,否则被风控),遇到 412
  风控会自动刷新 cookie 重试一次
- **粘贴解析**把一段文本拆成 token 逐个识别:
  - `b23.tv` 短链先跟随重定向拿到真实地址
  - 识别出 BV 号 / av 号(可带 `?p=N` 指定分P)/ 收藏夹 ID
  - 每个视频再调 `view` 接口取完整信息(含发布时间、分P列表)
  - 单P视频进播放队列;**多P视频自动聚合为歌单**;收藏夹整包创建歌单
- 解析结果按 `bvid:pN` 去重,并发控制为 3 个请求,避免触发 B站接口风控

### 三、歌单与备份

- 歌单存放在应用私有目录(`filesDir/galbums.json`),**无上限、永不自动删除**;
  每首曲目保存:标题、UP主、封面、时长、**发布时间**、视频标识(bvid/aid/cid,一键重播用)
- 曲目的发布时间在**加入歌单时**从 B站接口抓取;旧数据缺失时,**导出前会自动补齐**——
  导出歌单时逐个调用 B站 view 接口(并发 3)把缺失的发布时间补上再写文件,补齐结果
  同时写回歌单(下次导出不再重复请求)
- **导出 / 导入**(设置 → 歌单备份):
  - 导出:全部歌单合并为一个 JSON,`Json.encodeDefaults = true` 保证所有字段输出
  - 导入:同时兼容「全部歌单数组」和「单个歌单对象」两种文件格式;
    **同 ID 歌单覆盖、其余追加**,导入结果以 Toast 汇报(导入 N 个、覆盖 M 个)
  - 格式无法识别时提示"文件格式无法识别",不会动现有数据

### 四、听歌记录(何时记、地点怎么来)

- **记录时机**:只在真正切换歌曲时记一条(自动下一首 AUTO / 手动切歌 SEEK /
  单曲循环重复 REPEAT);恢复队列(PLAYLIST_CHANGED)与暂停后继续播放不算
- **地点获取**:不用 GPS、不申请定位权限,而是**查询网络出口 IP 的归属地**:
  1. 首选 **B站 zone 接口**(`api.bilibili.com/x/web-interface/zone`,HTTPS 国内直连,
     返回省 / 市,实测稳定)
  2. 失败退 **myip.ipip.net**(HTTPS,解析中文文本)
  - 结果缓存 **10 分钟**:同一个地方连播不重复请求;换网后自动重新查
  - 两个接口都失败 → 该条记录地点显示"未知地点",不影响播放
- **写入流程**:切歌时**先落盘**(地点为空,记录立即可见)→ 后台异步查 IP →
  查到后按时间戳**回填**该条记录;最新一条在查询期间显示"定位中…"
- **存储与导出**:`filesDir/history.json`,无上限、不自动删除;记录页可导出 CSV
  (UTF-8 BOM,Excel 直接打开中文不乱码)

### 五、播放链路

- 播放列表交给 **Media3 MediaSessionService**(前台服务):锁屏 / 通知栏控制、
  音频焦点、耳机拔出暂停均为框架内置;应用被杀后队列自动恢复
- **直链解析**:播放列表使用占位 URI(`shiyin://track`),`ResolvingDataSource` 在真正
  打开音频流时才调用 playurl 解析 CDN 直链,并为请求附加 `Referer`(B站 CDN 防盗链);
  直链结果缓存 20 分钟
- **失败处理**:CDN 返回 403(直链过期)→ 标记失效重新解析并从原进度继续播放;
  单曲解析/播放失败 → 自动跳下一首;连续 3 次失败 → 暂停并提示
- **音质三档**:低 / 标准 / 高,对应 DASH 音频流的不同码率档;切换时重建播放列表
  并保留进度

### 六、设置与持久化

- 所有设置(主题、玻璃参数、滑块动画参数、音质、倍速)存于 `filesDir/settings.json`,
  改动即时生效并持久化
- **版本号**由仓库根目录的 `VERSION` 文件统一管理;CI 每次构建读取它作为应用版本,
  构建成功后自动 +0.1 并提交回仓库(构建失败不消耗版本号),`versionCode` 取构建号
- **崩溃日志**:未捕获异常追加写入 `filesDir/crash.log`,设置页可一键导出排查

## 架构

```
app/src/main/java/com/shiyin/player/
├── MainActivity.kt          # 入口,组装 Compose;安装崩溃日志处理器
├── data/
│   ├── Models.kt            # Track / Galbum / Settings(主题与玻璃参数)/ QueueState
│   ├── AppStore.kt          # 持久化(filesDir JSON):队列 / 歌单 / 设置
│   └── PlayHistory.kt       # 听歌记录存储(时间 / 地点 / 歌曲,无上限不自动删除)
├── bili/
│   └── BiliApi.kt           # B站接口层:搜索(buvid+412重试)/视频信息/playurl 解析/
│                            #   UP主作品(老接口+wbi 签名兜底)/收藏夹/b23.tv/粘贴解析
├── util/
│   ├── IPLocation.kt        # IP 归属地查询(B站 zone 首选 + ipip.net,10 分钟缓存)
│   └── CrashLog.kt          # 崩溃日志落盘,设置页可导出
├── player/
│   ├── PlaybackService.kt   # Media3 MediaSessionService 前台服务
│   │                        #   ResolvingDataSource:占位 URI shiyin://track → 打开时解析直链 + Referer
│   └── PlayerBus.kt         # UI ↔ 服务桥,队列以 AppStore 为唯一真源;切歌时写听歌记录
└── ui/
    ├── Ui.kt                # 应用骨架:dock 玻璃底栏(玻璃滑块/左右滑动切 tab)+ 通用组件
    ├── Theme.kt             # 深色/浅色双主题色系
    ├── Search.kt            # 搜索页 + 粘贴解析弹窗(状态在对象层,切 Tab 不丢)
    ├── Pages.kt             # 歌单 Tab / 歌单详情 / UP主详情
    ├── History.kt           # 听歌记录 Tab(倒序列表/重播/CSV 导出/清空)
    ├── Settings.kt          # 设置 Tab(主题切换/玻璃参数/滑块动画/歌单备份/诊断日志导出)
    └── Player.kt            # 全屏播放页(下滑关闭/倍速/定时/音质)+ 队列抽屉 + 加入歌单弹窗
```

## 云端构建 APK(本机无需任何环境)

1. 在 GitHub 上新建一个**空仓库**(公开或私有均可)
2. 推送本目录:

   ```bash
   cd shiyin-android
   git init -b main
   git add -A
   git commit -m "拾音 Shiyin Android 初始版本"
   git remote add origin https://github.com/<你的用户名>/shiyin-android.git
   git push -u origin main
   ```

3. 打开仓库的 **Actions** 页,等待 "Build APK" 工作流跑完(首次约 5–10 分钟;
   构建失败时运行页顶部的 Summary 会自动列出编译错误)
4. 在该次运行详情页底部的 **Artifacts** 下载 `Shiyin-APK`,或到 **Releases** 页直接下载
   裸 APK(`Shiyin-v<版本>.apk`,免解压免登录)
5. 手机安装即可(允许安装未知来源应用)

> 首次构建会自动生成签名密钥 `keystore.jks` 并提交回仓库,保证后续每次构建签名一致,
> 可以直接覆盖安装、歌单数据不丢。私有仓库的 Actions 每月有免费额度(个人使用绰绰有余)。

## 限制

- 仅支持公开内容;部分版权/付费内容可能解析失败
- 定位精度为 IP 归属地级别(省 / 市),非 GPS 精确定位
- 仅供个人学习使用
